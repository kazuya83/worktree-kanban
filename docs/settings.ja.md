# 設定

トップバーの左端のメニューボタン（三本線）から **「設定」** を選ぶと、トップバーの下いっぱいに設定の画面が開きます。

左に項目の一覧、右にすべての項目が縦に並びます。左の項目を押すと、その節までスクロールします。右をスクロールすると、左の青いバーも今見ている項目に動きます。

## 保存のしかた

- 変更は、下の **「保存」** でまとめて保存します。保存しても画面はそのまま開いています
- **「元に戻す」** は、保存していない変更を捨てて、保存済みの値に戻します
- Pipeline の一覧の変更と、「CLI・MCP」の項目だけは、その場で保存します
- 保存しないまま別の画面やタブに移ると、変更は確認なしで捨てられます
- 起動したときは設定の画面ではなく、前に開いていたカンバン管理かタスクスケジューラに戻ります

「このプロジェクト」の項目と、下で「プロジェクトごと」と書いた項目は、プロジェクト（リポジトリ）ごとに覚えます。上部のタブを切り替えると、そのプロジェクトの設定に変わります。裏で動いているほかのプロジェクトのタスクも、そのプロジェクトの設定で動きます。初めて開いたプロジェクトは初期値から始まります。ほかの項目は、どのプロジェクトでも同じです。

この版より前から使っていたプロジェクトは、それまでの設定（取り込み方も含む）をそのまま引き継ぎます。

## 全般

| 項目 | 説明 |
| --- | --- |
| 同時に動かす数 | 1〜10 |
| 似た作業が続いたらスキルにしないか聞く | タスクが完了したとき、前に完了したタスクと似た作業が続いていたら通知で聞きます（右上のベル） |
| マージしたら会話を消す | マージして完了にしたタスク（PR がマージされたときも）が作業に使った Claude Code の会話を消します。引き継いだ元の会話は残します（初期値はオン） |

## アプリの更新

今の版と、新しい版があるかが出ます。左上の版の横に出る更新の知らせを押しても、ここが開きます。くわしくは [install.md](install.ja.md) を見てください。

## 連携

GitLab・Linear・Jira・Slack の接続先とトークンを入れます。どのプロジェクトでも同じです。サービスごとに「保存」「接続テスト」「削除」があります。トークンは保存したあとは画面に出ません。くわしくは [integrations.md](integrations.ja.md) を見てください。

## CLI と MCP

`wtk` コマンドと MCP サーバーが使う API を動かす（最初からオン）、`wtk` を入れる、エージェントにコピーする MCP の設定を出す、ほかの PC のためにペアリングコードを出す、ペアリングした PC の一覧と無効にする、ができます。どのプロジェクトでも同じで、その場で保存します。詳しくは [cli.ja.md](cli.ja.md) にあります。

## ブランチと取り込み

| 項目 | 説明 |
| --- | --- |
| ベースブランチ | worktree の作成元。マージ先の初期値にもなります。空ならチェックアウト中のブランチ |
| レビュー後の取り込み方 | **PR を作成する**（初期値。連携した GitLab のリポジトリでは **MR を作成する**）か **直接マージする** か。origin がない・GitHub でも連携した GitLab でもないリポジトリと、git で管理していないフォルダは「直接マージする」から始まります |
| ブランチの命名規則 | 自然言語で書いた規則に沿って、エージェントがブランチ名を考えます |
| セットアップ・片付け・実行スクリプト | worktree を作った直後・消す直前・詳細のボタンで動かすスクリプト（[使い方](usage.ja.md)） |
| タスクのポートを探し始める番号・1つのタスクに割り当てるポートの数 | タスクごとに分ける開発サーバーのポート。初期値は 20000 から 10 個ずつ |

マージのダイアログで選んだ「マージしたあと origin に push する」も、プロジェクトごとに覚えます。

| 項目 | 説明 |
| --- | --- |
| 使う課題管理サービス | GitHub・GitLab・Linear・Jira から選びます。「＋ 新しいタスク」の Issue の欄で使います |

## 権限

| 項目 | 説明 |
| --- | --- |
| 権限モード | `acceptEdits`（ファイル編集は自動、コマンドは承認）がおすすめ。`default` にすると、すべての操作をカードで承認します。`bypassPermissions`（すべて自動で許可）を選んでも、Issue から作ったタスクと Slack から頼んだタスク（そのサブタスクも）は `acceptEdits` で動きます。Issue の本文や Slack のメッセージは外の人が書けるので、そこから承認なしでコマンドが動かないようにするためです |
| Claude Code に最初から許可しておくツール | `--allowedTools` に渡します。例: `Bash(npm test:*), WebSearch` |

## タスクの既定

| 項目 | 説明 |
| --- | --- |
| 新しいタスクで最初から選んでおくスキル | 「＋ 新しいタスク」（自然言語・Issue のどちらでも）を開いたときに選ばれているスキル |
| 仕様を詰める | 新しいタスクの内容が詰まっていなければ、開発を始める前にエージェントが質問して仕様を詰めます（初期値はオン） |
| サブタスクが終わったら | 自動で親のブランチにマージするか、確かめてからマージするかの既定。タスクごとに開始前に変えられます |

## チームで共有

「このプロジェクト」の設定（スクリプト・ポート・ベースブランチ・取り込み方・権限・Pipeline・カスタムエージェント・競争など）を、リポジトリの `.worktree-kanban/settings.json` に置いてコミットすると、チームのほかの人の PC でも同じ設定になります。

- **「リポジトリのファイルに保存」** で、保存してある今のプロジェクトの設定をファイルに書き出します。コミットと push は自分で行います。トークンなどの秘密は書き出しません
- リポジトリを開いたとき・タブを切り替えたとき・アプリの画面に戻ってきたとき（`git pull` のあとなど）に、ファイルを読み直します
- ファイルにある項目は、ファイルの値を使います。この PC で設定画面から変えた項目だけは **「この PC で上書き中」** になり、この PC の値を使います。**「ファイルの値に戻す」** で、ファイルの値を使うように戻せます
- ファイルに書くのは使いたい項目だけでもかまいません。知らない項目や、値の形が違う項目は使いません。ファイルが読めないときは、前に読んだ値のまま動きます
- ファイルにあるセットアップ・片付け・実行スクリプトは、初めて動かすときと中身が変わったときに、動かしてよいかを確かめます（常駐モードでは聞けないので、遠隔操作の設定画面の **「今の中身で許可する」** で許可します）。許可しないと、セットアップスクリプトのときはエージェントを始めません

```json
{
  "version": 1,
  "settings": {
    "setupScript": "npm ci",
    "runScript": "npm run dev -- --port \"$WORKTREE_KANBAN_PORT\"",
    "portStart": 40000,
    "portCount": 4,
    "integration": "pr"
  }
}
```

## 使うエージェント

| 項目 | 説明 |
| --- | --- |
| 使うエージェント | Claude Code / Codex CLI / Antigravity CLI / Gemini CLI / Cursor CLI / OpenCode / Copilot CLI / Amp / Pi / Droid のうち、使うものにチェックを付けます。チェックを付けたものだけ、下の項目を設定でき、タスク・会話・Pipeline・競争で選べます |
| （エージェントごと）コマンドのパス | Finder などから起動してコマンドが見つからないときに、フルパスを指定します |
| （エージェントごと）モデル | `--model` / `-m` に渡します。空なら既定のモデル |
| 新しいタスク・会話で最初から選んでおくもの | 新しいタスク・会話を開いたときに選ばれているもの（プロジェクトごと。使うエージェント・このプロジェクトのカスタムエージェント・Pipeline・競争の中から1つ。Pipeline・競争を選んだときも、会話と、使えない状態のときは使うエージェントの先頭になります。選んだものを消したり、元にするエージェントを使わない設定にしたりしたときは、使うエージェントの先頭に戻ります） |

## カスタムエージェント

元にするエージェント（CLI）とモデルに、名前・アイコンと色・説明・振る舞いの指示を持たせます（プロジェクトごと。[agents.md](agents.ja.md)）。

## オーケストレーション

Pipeline・競争の設定です。どちらもプロジェクトごとにいくつでも作れて、タスクを作るときの「エージェント」の欄で1つ選びます。Pipeline は「フローチャートを編集」で、工程・分岐（if）・ループ・並列・合流をつないだフローチャートを組みます（`.json`・zip でのエクスポート・インポートもここから）。競争は、名前と、同じタスクを解かせるエージェント（2つ以上）を決めます。くわしくは [agents.md](agents.ja.md)。

## ここにない設定

遠隔操作（RC）の設定は、メニューの設定ではなく、上部の **「RC設定」** にあります（[remote.md](remote.ja.md)）。

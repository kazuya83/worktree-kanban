# エージェントとオーケストレーション（🤖 / 🔁 / 🏁）

タスクを作るときの「エージェント」で、**Claude Code / Codex CLI / Antigravity CLI / Gemini CLI / Cursor CLI / OpenCode / Copilot CLI / Amp / Pi / Droid** のどれで動かすかを選べます（メニューの設定の「使うエージェント」でチェックを付けたものだけが出ます）。さらに、複数のエージェントを組み合わせる **オーケストレーション** も選べます。

| 選び方 | 動き方 |
| --- | --- |
| Claude Code / Codex CLI / Antigravity CLI / Gemini CLI / Cursor CLI / OpenCode / Copilot CLI / Amp / Pi / Droid | そのエージェントで1枚のカードとして動きます（worktree・コミット・マージ・PR はこれまでと同じ） |
| 🔁 Pipeline | 設定の **フローチャート** に沿って、工程ごとにエージェントが作業を引き継ぎます（例: Codex で実装 → Claude でレビュー → 差し戻しなら実装へ戻る）。工程は同じ worktree で動き（並列の枝だけは別の worktree）、工程が終わるたびに変更をコミットし、最後の報告を次の工程に渡します。途中の工程が失敗・質問で止まったら、そこで止まります（追加指示で直すと、続きの工程へ進みます）。すべての工程が終わるとレビュー列に入ります。進み具合は、カードのバーと、詳細のワークフロー（工程ごとの状態・エージェント・かかった時間・金額・次へ渡した報告）で確かめられます |
| 🏁 競争 | 同じタスクを、設定のエージェントそれぞれのカード（別々の worktree・ブランチ）で **並列に** 解きます。全員が終わると通知が届きます。詳細の「進捗」タブの「🏁 競争」の欄で候補を見比べ、「🤔 ○○ に比べてもらう」で比較の会話を始めたり（最初から選んでおくエージェントに頼みます）、「🏁 この案を採用」でほかの候補を破棄したりできます。採用した案は、いつもどおりマージ・PR の作成で取り込みます |

- メニューの設定の「使うエージェント」で、使うエージェントにチェックを付けます（1つ以上）。チェックを付けたものだけ、コマンドのパスとモデルを設定でき、タスク・会話・Pipelineの工程・競争で選べます（初めて起動したときは、インストールされているエージェントすべてにチェックが付きます。見つからないときは Claude Code だけで、次に起動したときにまた探します。前のバージョンから入れ替えたときは、使っていたエージェントにチェックが付きます）
- 新しいタスク・会話で最初から選んでおくエージェントは、プロジェクトごとに、使うエージェントかこのプロジェクトのカスタムエージェントの中から1つ選びます（カスタムエージェントを選んだときも、競争の比較・フローチャートの組み立ては、その元にするエージェントに頼みます）。Pipeline・競争（設定で選んだ方）は、タスクを作るときに「エージェント」の欄で選びます。オーケストレーションで Pipeline・競争を選んでいれば、タスクを作るときはそちらを最初から選んでおきます（工程のエージェントを使わない設定などで使えないときは、最初から選んでおくエージェント）
- メニューの設定の「オーケストレーション」で、**Pipeline**（「フローチャートを編集」から開く画面で組みます。プロジェクトごとにいくつでも作れます）と **競争させるエージェント**（2つ以上）を決められます
- **Pipeline を複数持つ**: 「＋ Pipelineを追加」で名前を付けて足し、Pipeline ごとに「フローチャートを編集」「名前」「複製」「既定にする」「削除」ができます（最後の1つは消せません）。タスクを作るときの「エージェント」の欄に Pipeline がすべて並び、「既定」の Pipeline を最初から選んでおきます。作ったタスクは、あとで Pipeline を直したり消したりしても、作ったときのフローのまま動きます
- **エクスポート**: Pipeline ごとの「エクスポート」で、その Pipeline だけを `.json` に書き出します。「まとめてエクスポート（zip）」（Pipeline ごとの「zip」も）では、書き出す Pipeline とカスタムエージェントを選んで1つの zip にします（選んだ Pipeline の工程で使っているカスタムエージェントには、最初からチェックが付きます）
- **インポート**: 「インポート（.json / .zip）」で、Pipeline の `.json` か、まとめた zip を選びます。取り込むものを確かめてから、今の一覧に足します（同じ名前があれば「名前 (2)」）。カスタムエージェントは、同じ中身のものがあればそれを使い、なければ足して、工程のエージェントをそれに付け替えます。カスタムエージェントの入っていない `.json` を取り込んで、工程のカスタムエージェントが見つからないときは、フローチャートで選び直します
- **フローチャートの編集**: 「＋ 工程」「＋ 分岐（if）」「＋ 並列」「＋ 合流」「＋ 終了」でノードを足し、ドラッグで並べます。ノードも線もないところをドラッグすると、キャンバスをスクロールできます。ノードの下の丸（出口）から別のノードへドラッグすると線をつなげます。ノード・線を選ぶと右の欄で中身（工程のエージェント・名前・担当の説明、分岐の期待値・条件、ループの上限）を変えられ、Delete キーで消せます。工程でカスタムエージェントを選んだとき、工程の名前が空なら、そのカスタムエージェントの名前が入ります（空のまま保存したときも同じです）。右上の「－」「＋」「全体」のボタンか、⌘（Windows・Linux は Ctrl）を押しながらのスクロール・トラックパッドのピンチで拡大・縮小できます（倍率の欄を押すと 100% に戻ります）。直すところがあるうちは下に一覧が出て、保存できません。「保存」ですぐにこのプロジェクトの設定に保存します（前のバージョンの工程のリストは、フローチャートに移してあります）
- **分岐（if）**: 工程のすぐあとに置きます。その工程のエージェントに、返事の最後へ `[[RESULT:値]]` を書いてもらい、分岐から出る線ごとに決めた **期待値**（例: `ok` / `bug` / `docs`。大文字・小文字は区別しません）と比べて行き先を選びます。線は3本以上でもかまいません。線の **条件の説明** は、どんなときにその値を書くかとしてエージェントに伝えます。どの期待値にも合わない（書かなかった）ときは「どれにも合わないとき」にした線へ進み、その線もなければ止めて知らせます（追加指示で書き直してもらえば、続きへ進みます）
- **文章でフローチャートを作る・直す**: 編集画面の上の欄に、作りたいフローや直したいところを文章で書いて「AIで反映」（⌘〈Windows・Linux は Ctrl〉＋Enter）を押すと、エージェントがフローを組み立てて画面に反映します（例: 「Codex で実装して Claude でレビューし、直すところがあれば実装に戻す」「レビューの工程の前にテストの工程を足して」）。組み立てるのは「最初から選んでおくエージェント」です（使わない設定なら、使うエージェントの先頭）。工程には、使うエージェントとカスタムエージェントだけを選びます。ノードや線が変わったときは、配置を自動で並べ直します。「保存」を押すまで設定は変わりません。「元に戻す」で反映の前に戻せます。形が直しきれなかったときは、下の「直すところ」に出ます
- **ループ**: 前のノードへ戻る線を引くとループになります（点線で表示）。線ごとに「戻る上限」（初期値 3 回・1〜10 回）を決められ、上限に達したら Pipeline を終えてレビュー列に入れて知らせます
- **並列 → 合流**: 並列から線を2本以上出し、それぞれの枝の最後を同じ合流につなぎます。枝ごとに、このタスクのブランチから分けた別の worktree で「枝のタスク」（ボードにカードが出ます）を同時に動かします。すべての枝が合流まで来たら、枝の変更を順にこのタスクのブランチへマージし、枝のタスクを片付けて先へ進みます。どれか1つの枝が失敗・質問で止まったら、元のタスクは待ったままです（枝のタスクで直すか答えると、続きから進みます）。マージがコンフリクトしたら止めて知らせ、詳細の「チャット」タブの最後の「コンフリクト」の欄から解消すると、残りの枝のマージと次の工程へ進みます。枝の中にもう1つの並列は置けません。git で管理していないフォルダでは、枝ごとに作業場所を分けられないので、枝のタスクを同じフォルダで1本ずつ順に動かし、すべての枝が終わったらマージせずに合流の先へ進みます
- 詳細のワークフローでは、工程ごとの状態・実行回数・判定の値・戻った回数・飛ばした工程（スキップ）・並列の枝の状態を確かめられます
- レビューや失敗で止まっているときは、工程や各回の直前の時点へ戻せます。ファイル・進み具合・会話をその時点に戻し、あとの変更は捨てて、すぐに動き始めます。くわしくは [途中の状態に戻す](usage.ja.md#途中の状態に戻す)
- **Pipelineと競争は排他** です。メニューの設定の「オーケストレーション」の「使うオーケストレーション」でどちらか1つ、または「なし」を選びます（初期値はPipeline）。選んだ方だけ、その設定欄が出て、タスクを作るときに選べます。「なし」にすると、タスクを作るときの「エージェント」の欄には1つのエージェントだけが出ます。選んでいない方の設定は消えずに残るので、切り替えればまた使えます
- ブランチの命名・コンフリクトの解消・仕様の確認・会話・スキルの提案も、どのエージェントでも動きます（ブランチ名とコンフリクトの解消は、そのタスクのエージェントが行います）
- Issue から作るときも、同じようにエージェント・Pipeline・競争を選べます（競争なら、1つの Issue につきエージェントの数だけカードができます）
- Codex は `codex exec --json`（カードで承認するときは `codex app-server`）、Antigravity は `agy --output-format stream-json`、Gemini は `gemini --output-format stream-json`、Cursor は `cursor-agent acp`（使えない版では `cursor-agent -p --output-format stream-json`）、OpenCode は `opencode run --format json`、Copilot CLI は `copilot -p … --output-format json`、Amp は `amp -x --stream-json`（続きは `amp threads continue`）、Pi は `pi --mode json`、Droid は `droid exec -o stream-json` で動かし、追加指示は同じ会話の続きから動きます
- Codex / Antigravity / Gemini / Cursor / OpenCode / Copilot / Amp / Pi / Droid は、CLI の作りの都合で、選択肢の質問・btw（実行中のメッセージ）・既存の会話（ターミナルの会話）の引き継ぎ・使った金額の表示には対応していません
- **カードでの承認**は Claude Code・Codex・Cursor で使えます。「常に許可」はそのカードの中だけ覚えます。設定の「許可しておくツール」も効きます（`Bash(npm test:*)` のような前方一致は、`;` や `|` でつないだコマンドには効きません）。権限モードごとの動きは次のとおりです

| 権限モード | Codex | Cursor | Antigravity | Gemini |
| --- | --- | --- | --- | --- |
| 計画だけ | 読み取りのみの sandbox | plan モード | `--mode plan` | `plan` |
| ファイル編集は自動（`acceptEdits`） | worktree の中の編集と sandbox の中のコマンドはそのまま動き、sandbox から出る操作（ネットワーク・worktree の外への書き込みなど）を **カードで承認** | ファイル編集はそのまま動き、Cursor の `cli-config.json` の allow にないコマンドを **カードで承認** | worktree の中のファイル編集だけ自動で許可（`--mode accept-edits`） | ファイル編集だけ自動で許可（`auto_edit`） |
| 毎回確認する（`default`） | コマンドとファイルの変更を **カードで承認** | allow にないコマンドを **カードで承認**（ファイル編集は Cursor が承認を聞いてこないので、そのまま書かれます） | 変更は拒否（`default`） | `default` |
| すべて自動で許可 | `--dangerously-bypass-approvals-and-sandbox` | `--force --approve-mcps` | `--dangerously-skip-permissions` | `yolo` |

OpenCode・Copilot CLI・Amp・Pi・Droid はカードでの承認に対応していないので、権限モードに合わせて CLI 側で許可します。確認が要る操作は、ヘッドレスでは聞き返せないので、その場で断られます（待ち続けません）。OpenCode・Amp・Pi はもともと確認なしでコマンドを動かすので、「すべて自動で許可」以外ではコマンドを止めて動かします（Issue・Slack から作ったタスクは「すべて自動で許可」にならないので、外の人が書いた指示からコマンドが動くこともありません）

| 権限モード | OpenCode | Copilot CLI | Amp | Pi | Droid |
| --- | --- | --- | --- | --- | --- |
| 計画だけ | `--agent plan`（ファイルの変更を断る）。コマンドは確認（＝断られる） | `--plan` | ファイルを変えるツールとコマンド（`edit_file` / `create_file` / `undo_edit` / `Bash`）を止める | 読み取りのツールだけ（`--tools read,grep,find,ls`） | 何も付けない（読み取りのみ） |
| ファイル編集は自動（`acceptEdits`） | コマンドは確認（＝断られる） | ファイルの書き込みだけ許可（`--allow-tool=write`） | コマンド（`Bash`）を止める | コマンドなし（`--tools read,edit,write,grep,find,ls`） | `--auto low`（ファイルの編集まで） |
| 毎回確認する（`default`） | ファイル編集・コマンド・Web の取得を確認（＝断られる） | 何も許可しない | コマンド（`Bash`）を止める | コマンドなし | 何も付けない（読み取りのみ） |
| すべて自動で許可 | `--auto` | `--allow-all` | `--dangerously-allow-all` | 制限なし | `--skip-permissions-unsafe` |

- OpenCode の許可は、環境変数 `OPENCODE_CONFIG_CONTENT` の `permission` で渡します（ふだんの `opencode.json` に重ねて読まれます）。Amp は、ふだんの設定（`~/.config/amp/settings.json`）を写して `amp.tools.disable` を足した設定ファイルを `--settings-file` で渡します
- テストなどのコマンドも動かしたいときは「すべて自動で許可」を選びます。Droid は、許されない操作（「ファイル編集は自動」でのコマンドなど）をしようとすると、その場で実行が終わり、カードがエラーになります（それまでの編集は残ります）
- Copilot CLI は指示を `-p` の引数で渡します。ヘッドレスでは聞き返せないので `--no-ask-user` を付けます。添付ファイルの置き場所は `--add-dir` で読めるようにします
- Amp をヘッドレスで動かすには、環境変数 `AMP_API_KEY`（`sgamp_…`）が要ります（`amp login` のセッションでは動きません）。モデルは選べないので、設定やタスクの「モデル」は `--mode`（`low` / `medium` / `high` / `ultra` など）に渡します
- Droid をヘッドレスで動かすには `FACTORY_API_KEY` が要ります
- Pi は応答が失敗しても終了コードが 0 なので、出力の `stopReason` を見てエラーにします。TODO は出さないので、進捗タブの TODO は空のままです（Copilot CLI も、出力に TODO の中身が入らないので空のままです）
- OpenCode は作業フォルダを `PWD` から決めるので、worktree のパスを `PWD` にも入れて起動します
- Codex は app-server の仕様が版によって変わるので、動かす手前で使えるかを確かめます。Cursor も同じです。使えない版では、前のやり方（Codex は `workspace-write` の sandbox、Cursor は `--force`）で動かし、ログにそのことを出します。確かめた版は Codex 0.150.0 と 0.167.0、Cursor 2026.11.05 です
- Cursor の `acp` と `-p` は会話の保存場所が別なので、前の版で `-p` で始めたカードは、そのまま `-p` で続けます（カードで承認はできません）。新しく始めた会話から承認できます
- Antigravity は、許可されていないコマンドをその場で拒否します（ヘッドレスでは確認を出せないため）。テストなどのコマンドを動かしたいときは、`~/.gemini/antigravity-cli/settings.json` の `permissions.allow` に `"command(npm test)"` のように書くか、「すべて自動で許可」を選びます
- Antigravity は、最初に一度ターミナルで `agy` を起動してログインしておきます。ログインしていないと、カードに認証のエラーが出ます
- Gemini CLI は、2026年6月18日で Google AI Pro / Ultra と無料の個人アカウントでは使えなくなりました（[Google の案内](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)）。有料の API キーや Gemini Code Assist の Standard / Enterprise なら引き続き使えます。個人のアカウントでは Antigravity CLI を選んでください
- スキルを選ぶと、Claude Code には `/スキル名` で、ほかのエージェントには SKILL.md の場所を伝えて手順に従ってもらいます
